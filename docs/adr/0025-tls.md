# ADR 0025: Encrypted connections (TLS)

- Status: accepted
- Date: 2026-11-10

## Context

`fetch` could ask only servers that answer in the clear, which today is
almost none of the web. Everything that is to talk to the outside world
later needs connections that are private and that reach the server they
were meant for.

## Decision

- **The protocol is not written here.** It is the `rustls` library, and
  the cryptography under it is the RustCrypto project's, through the
  `rustls-rustcrypto` provider. Both are pure Rust and build for a
  system without a standard library; the usual providers of rustls
  (written partly in C and assembly) do not.
- `userspace/tls` (`omit-tls`) is the piece in between: it drives
  rustls's buffer-less interface over any byte stream and offers
  connect, read, write and close. It runs on the host too, where it is
  tested against a real TLS server.
- TLS 1.3 only. A server's certificate must lead to an authority in
  Mozilla's list (the `webpki-roots` crate; the authorities are listed
  in `docs/TRUSTED_AUTHORITIES.md`) or to one the caller names, be valid
  by the system's clock, and be for the name asked for.
- Random numbers come from the kernel (ADR 0024). When they rest on
  timing alone, `fetch` prints a warning with every encrypted
  connection.
- A connection that ends without the server having said so in the
  protocol is an error, not an end: what came before may have been cut
  short by someone in between.
- In the kernel, nothing changes: TLS is a library of programs.
- `fetch` takes `https://` addresses, and `--trust FILE` for an
  authority of one's own (PEM or DER).

## What it rests on, and what that is worth

- `rustls` is widely used and has been audited. **`rustls-rustcrypto`
  has not**: it is an early release (pinned here to one exact version),
  and its authors say it is not ready for production. The primitives it
  wires up are the RustCrypto crates, of which some have been audited
  and some not.
- Native programs are built for a target without floating-point and
  vector instructions (the kernel does save the SSE registers of
  threads, for Windows programs; native ones are not built to use
  them, and AVX is not enabled at all), so every primitive runs in its
  portable form: correct, slow, and with whatever resistance to timing
  attacks the portable code has — which nobody has measured on this
  system.
- **Nothing learns of revoked certificates**, and the list of
  authorities is as old as the release it was built into.
- The clock is the machine's (ADR 0021); a wrong clock makes valid
  certificates look expired or the reverse.

So: this keeps a connection away from casual eyes and from servers that
merely claim a name. It should not yet carry anything whose secrecy
matters.

## What works

- 12 host tests of `omit-tls` against rustls's own server on the same
  machine, with certificates made for the run by the `openssl` command:
  data both ways, a megabyte down and 300 KB up intact; a server no
  authority vouches for, one with a certificate for another name or
  address, and certificates judged expired, not yet valid, or
  unjudgeable for want of a clock, all refused with a sentence that
  says which; a connection that just stops reported as cut off; PEM and
  DER reading of trusted certificates.
- The `network` QEMU test runs the test web server a second time behind
  TLS and has the guest fetch from it: a small file, the megabyte-sized
  desktop program (compared byte for byte), a body without a stated
  length; and be refused without the authority, when the connection is
  cut, with a file that is no certificate, and by a server that does
  not speak TLS. In the `qemu64` configuration the same runs on a
  processor without a random number instruction, with the warning.
- **Not tested: any server on the Internet.** The tests cannot reach
  one; the first real `https://` fetch will be someone's by hand.

## Limits

- No TLS 1.2, so servers that offer nothing newer cannot be reached.
- No client certificates, no session resumption, no ALPN.
- `fetch` still speaks HTTP/1.0 without redirects or compression.
- `fetch` grows from about 54 KB to about 1.3 MB.
